# PhysicsTech — веб-приложение (React + TypeScript + Vite)

Новый фронтенд тренажёра. Работает локально в браузере, в будущем станет Telegram Mini App.
Учебный контент, генераторы задач, проверка ответов, правила зачёта и калькулятор — те же, что в текущем приложении `frontend/index.html`; совпадение проверяется автотестами.

## Что нужно

- Node.js 22 или новее (проверено на Node.js 26 LTS).
- Для режима с сервером — запущенный бэкенд PhysicsTech (`backend/`, см. README в корне проекта).

## Установка и запуск

```bash
cd webapp
npm install
npm run dev
```

Откройте http://localhost:5173. По умолчанию приложение работает **без сервера**: прогресс хранится в браузере.

### Режим с сервером

1. Запустите бэкенд с `DEV_AUTH=true` (в корне проекта: `docker compose up -d`, в `.env` — `DEV_AUTH=true`, `ADMIN_TELEGRAM_IDS=1`).
2. Создайте файл `webapp/.env.local` (образец — `.env.example`):

```
VITE_DATA_MODE=api
VITE_DEV_USER=1:Тест
```

3. Перезапустите `npm run dev`. Запросы `/api` Vite перенаправляет на `http://localhost:8000` (`VITE_PROXY_TARGET`).

Другого тестового пользователя можно открыть адресом `http://localhost:5173/?dev_user=2:Студент`.

### Режим демо-данных

`VITE_DATA_MODE=mock` — экраны профиля и статистики работают без сервера на вымышленных данных; вверху показывается баннер «Демо-данные».

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | режим разработки, http://localhost:5173 |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run preview` | просмотр собранной версии, http://localhost:4173 |
| `npm test` | автотесты (Vitest) |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run extract` | заново перенести контент из `../frontend/index.html` |

## Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `VITE_DATA_MODE` | `local` | `local` — только браузер; `api` — сервер; `mock` — демо-данные |
| `VITE_API_BASE_URL` | пусто | адрес сервера; пусто — тот же адрес, что у приложения |
| `VITE_PROXY_TARGET` | `http://localhost:8000` | куда dev-сервер перенаправляет `/api` |
| `VITE_DEV_USER` | пусто | тестовый пользователь `ID:Имя` (сервер должен быть запущен с `DEV_AUTH=true`) |

Секретов во фронтенде нет и быть не должно.

## Архитектура

```
src/
  app/          каркас: маршруты (hash-роутинг), шапка, нижняя панель (телефон), боковое меню (компьютер)
  pages/        страницы
  components/   ui/ — кнопки, карточки, индикаторы, иконки; learning/ — вопрос, задача, подсказки, решение; math/ — KaTeX
  features/
    progress/   прогресс (тот же ключ localStorage, что у старого приложения), освоение тем, путь обучения, очки и достижения
    practice/   подбор и проверка заданий, подсказки, сессии
    exam/       симуляция дифференцированного зачёта
    account/    вход, синхронизация с сервером, учёт времени
    calculator/ интерфейс калькулятора
  api/          настройки, типы контрактов бэкенда, HTTP-клиент, mock/ — демо-данные
  auth/         абстракция входа (локально, тестовый вход; Telegram — позже)
  platform/     тема и размеры экрана; сюда позже подключается Telegram (viewport, safe area)
  legacy/       контент, движок формул и калькулятора, перенесённые из старого приложения без изменений
  i18n/ru.ts    строки интерфейса
  styles/       дизайн-токены и общие стили
tests/          parity.test.ts — сравнение со старым приложением; logic.test.ts — логика нового приложения
```

Принципы:
- Бизнес-логика — в `features/`, страницы только показывают данные.
- Все запросы к серверу — через `api/` (интерфейс `ApiClient`); заменить демо-данные на сервер — одна переменная.
- Формат прогресса и сохранённых попыток совпадает со старым приложением: можно переходить между ними без потери данных.

## Страницы

| Адрес | Страница |
|---|---|
| `#/` | Главная: приветствие, «Продолжить», цель на день, серия, прогресс, рекомендуемая тема, зачёт, недавняя активность, слабые темы |
| `#/path` | Путь обучения: механика и термодинамика, пройденные/доступные/закрытые темы |
| `#/topic/:id` | Теория темы: определения по Савельеву, формулы (KaTeX), пример, ошибки, связанные упражнения |
| `#/practice`, `#/session` | Тест и задачи с проверкой, подсказками (4 ступени), формулой и разбором |
| `#/problems`, `#/problems/:id` | Типы задач: алгоритм, разобранный пример, похожая и усложнённая задача |
| `#/errors` | Работа над ошибками |
| `#/exam`, `#/exam/run`, `#/exam/result` | Дифференцированный зачёт: правила, режимы экзамена и тренировки, результат и разбор |
| `#/progress` | Прогресс и достижения: очки, уровень, неделя, достижения, темы, рекомендации, история зачётов |
| `#/profile` | Профиль: данные, синхронизация, время в приложении, настройки (тема, цель на день), импорт/экспорт, сброс |
| `#/formulas`, `#/formulas/lab`, `#/trig` | Справочник формул, практика с формулами, тригонометрическая таблица |
| `#/admin`, `#/admin/:id` | Статистика пользователей (только администратор, режим `api`) |

Калькулятор (вычисления, производная, интеграл) доступен на всех экранах; кнопка «В ответ» подставляет результат в поле ответа без открытия клавиатуры телефона.

## Очки, серия, достижения, закрытые темы

Сервер этих данных не хранит — всё считается в приложении из журнала ответов (последние 1500, как и в старом приложении):
- очки: 10 за верный ответ на вопрос, 20 за верно решённую задачу; цель на день — 50 очков (меняется в профиле);
- серия — дни подряд хотя бы с одним ответом;
- 12 достижений по реальным данным (первый ответ, теория тем, задачи, серии, зачёт и т. п.);
- тема открывается, когда по предыдущей прочитана теория или есть 3 ответа; закрытую тему можно изучить досрочно.

## Демо-данные и незавершённые интеграции

- `src/api/mock/mockClient.ts` — вымышленные пользователь и статистика для режима `mock`. В режимах `local` и `api` не используются.
- Вход через Telegram не подключён (по заданию этапа). Место подключения — `src/auth/auth.ts` (провайдер `telegram` будет отправлять `Authorization: tma <initData>`, сервер это уже проверяет) и `src/platform/platform.ts` (тема, viewport, safe area).
- Отдельного «решателя» задач нет: задачи создаются существующими генераторами с готовым решением по шагам.
- Сервер пока отдаёт старую страницу `frontend/index.html`. Чтобы он отдавал новое приложение, соберите `npm run build` и укажите `FRONTEND_DIR=…/webapp/dist` — это следующий шаг, не сделан.

## Тесты

`npm test` — 20 тестов:
- сравнение со старым приложением (оно загружается в jsdom): одинаковые задачи для одинаковых seed по всем 93 генераторам, проверка ответов и диагностика ошибок, разбор чисел, освоение тем, шкала оценок, варианты ответов, чтение сохранённых попыток в обе стороны, калькулятор;
- логика нового приложения: очки, серия, достижения, открытие тем, запись ответов, подсчёт баллов зачёта.
