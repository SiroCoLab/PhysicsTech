# PhysicsTech — тренажёр по физике (Telegram Mini App) с сервером на Python

## Что это

- **Приложение** (`frontend/index.html`) — тот же PhysicsTech, что был в `physicstech demo.html`: теория, задачи, генераторы задач, калькулятор, симуляция зачёта. Всё по-прежнему работает в браузере и без сервера.
- **Сервер** (`backend/`, Python 3.12 + FastAPI + PostgreSQL) добавляет:
  - вход через Telegram (подпись данных Mini App проверяется на сервере);
  - сохранение прогресса на сервере и одинаковый прогресс на всех устройствах;
  - учёт времени, проведённого в приложении (только пока оно открыто на экране);
  - экран **«Статистика пользователей»** для администратора: Telegram ID, имя, время сегодня / за 7 дней / всего, ответы и точность, попытки зачёта и оценки, время по дням, выгрузка в CSV (Excel).

## Структура

```

  frontend/index.html          готовая страница приложения (собирается скриптом, см. ниже)
  frontend/src/sync.js         синхронизация с сервером и экран статистики
  frontend/src/bank_ext.js     новые вопросы и задачи по учебнику Савельева
  tools/build_frontend.py      сборка frontend/index.html из исходной страницы
  backend/app/                 сервер: вход, синхронизация, время, статистика
  backend/migrations/          миграции базы данных (Alembic)
  backend/tests/               автотесты (pytest)
  backend/Dockerfile           образ сервера
  docker-compose.yml           PostgreSQL + сервер (+ Caddy для HTTPS)

```

## 1. Проверка на своём компьютере (Windows, Docker Desktop)

1. Скопируйте `.env.example` в `.env` и заполните `POSTGRES_PASSWORD`. Для проверки без Telegram поставьте `DEV_AUTH=true` и `ADMIN_TELEGRAM_IDS=1`.
2. В папке проекта выполните:

```bash
docker compose up -d --build
```

3. Откройте http://localhost:8000/?dev_user=1:Тест — вход выполнится от имени пользователя с ID 1. На вкладке «Прогресс» появится карточка «Аккаунт и синхронизация» и кнопка «Статистика пользователей».
4. Остановить: `docker compose down`. Данные базы сохраняются в томе Docker; полностью удалить их можно командой `docker compose down -v`.

> `DEV_AUTH=true` — только для своего компьютера. На сервере всегда `DEV_AUTH=false`.

## 2. Запуск на сервере (нужен HTTPS)

Telegram открывает Mini App только по адресу `https://…`. Нужны сервер (VPS с Linux и Docker) и домен, направленный на IP сервера.

1. Скопируйте папку проекта на сервер и создайте `.env`:
   - `BOT_TOKEN` — токен **вашего существующего бота** из @BotFather;
   - `ADMIN_TELEGRAM_IDS` — ваш Telegram ID (можно несколько через запятую);
   - `POSTGRES_PASSWORD` — длинный пароль;
   - `DOMAIN` — домен, например `physics.example.ru`;
   - `DEV_AUTH=false`.
2. Запустите вместе с HTTPS (сертификат Caddy получит сам, порты 80 и 443 должны быть открыты):

```bash
docker compose --profile https up -d --build
```

3. Проверьте в браузере `https://ваш-домен/api/health` — ответ `{"status":"ok"}`.

## 3. Подключение к боту

Код бота менять не нужно — бот просто открывает страницу. В @BotFather: `/mybots` → ваш бот → **Bot Settings** → **Menu Button** → укажите адрес `https://ваш-домен/`. Тот же адрес можно указать и в `/newapp`, если приложение у бота уже заведено как Mini App.

После этого:
- студенты открывают приложение из бота, и их прогресс автоматически сохраняется на сервере;
- у администратора на вкладке «Прогресс» есть кнопка **«Статистика пользователей»**.

## 4. Как сохраняется прогресс (существующие данные не теряются)

- Прогресс по-прежнему сначала записывается на устройство (`localStorage`, прежний ключ `phys_trainer_mech_v1`), затем отправляется на сервер.
- При первом запуске с сервером уже накопленный на телефоне прогресс **загружается на сервер**. Если на сервере уже есть прогресс с другого устройства, они объединяются: ответы, история зачётов и отметки складываются, лучший результат сохраняется.
- Без связи приложение работает как раньше и отправит данные позже.
- Если на одном устройстве сменился аккаунт Telegram, прогресс прежнего аккаунта откладывается в отдельную копию на устройстве (`phys_trainer_mech_v1_backup_<ID>`) и не смешивается с новым.
- Кнопка «Сбросить прогресс» сбрасывает прогресс студента и на сервере; статистика администратора (ответы, зачёты, время) при этом сохраняется.

## 5. Какие данные хранятся

Telegram ID, имя, фамилия и username из Telegram, прогресс обучения, ответы, попытки зачёта и время работы в приложении. Пользователь видит это предупреждение в карточке «Аккаунт и синхронизация». Это персональные данные: храните их на своём сервере, ограничьте доступ к `.env` и базе. Если тренажёр используется официально от имени вуза, уточните требования 152-ФЗ (согласие на обработку, политика конфиденциальности).

## 6. Резервные копии базы

```bash
docker compose exec -T db pg_dump -U physicstech -d physicstech > backup-physicstech.sql
```

Восстановление в пустую базу:

```bash
docker compose exec -T db psql -U physicstech -d physicstech < backup-physicstech.sql
```

На сервере команду копирования удобно поставить в cron (ежедневно) и хранить копии вне сервера.

## 7. Если страница остаётся на GitHub Pages

Можно оставить `index.html` на GitHub Pages, а сервер запустить отдельно. Тогда:
- в `frontend/index.html` в строке `<meta name="api-base" content="">` укажите адрес сервера, например `https://api.example.ru`;
- в `.env` сервера задайте `CORS_ORIGINS=https://ваш-логин.github.io`.

Проще и надёжнее вариант из раздела 2: сервер сам отдаёт страницу, адрес у бота один.

## 8. Для разработки

Автотесты сервера (Python 3.12):

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```

Пересборка страницы после правок в `frontend/src/*.js`:

```bash
python tools/build_frontend.py
```

Скрипт берёт исходную страницу из `backup/`, проверяет её контрольную сумму и каждую правку (если что-то не совпадёт, сборка остановится, а не испортит файл). Документация API — `https://ваш-домен/api/docs`.

## Что изменено в самом приложении

1. Удалена разметка, сохранённая браузером при «Сохранить как» (приложение рисует её само при запуске; иначе дублировались элементы).
2. Симуляция дифференцированного зачёта снова собирается только из тем механики (официальный перечень вопросов 1–37). После добавления блока термодинамики в зачёт могли попадать вопросы по термодинамике.
3. Добавлено 32 теоретических вопроса и 13 типов расчётных задач по учебнику Савельева (со ссылками на параграфы); прежние вопросы и их номера не менялись, поэтому сохранённый прогресс остаётся корректным.
4. Добавлены синхронизация с сервером, учёт времени и экран «Статистика пользователей».

Генераторы задач по-прежнему работают в браузере.
